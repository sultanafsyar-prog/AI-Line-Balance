# IE 產線平衡系統－產品需求文件

**文件版本：** 1.0  
**產品狀態：** 正式環境使用中  
**主要語言：** 印尼文、英文、繁體中文  
**適用對象：** 工業工程（IE）、生產、PPIC、生產管理與 IT

## 1. 產品概述

IE 產線平衡系統是一套鞋類生產管理 Web 應用程式，用於管理 IE 標準資料，並與每小時的實際生產結果進行比較。系統將 IE 標準、型體與產線配置、實際產量輸入、產線監控、班次封存、分析及營運報表整合為一個具權限控制的工作流程。

本產品適用於同一條產線在同一班次內同時或先後生產多個型體／款式的情境。每筆實際資料都會連結至產線、型體工段、生產日期與時段，因此歷史紀錄可以追溯哪一個款式、在哪一條線、什麼時間生產，以及實際產量。

## 2. 問題說明

生產與 IE 團隊需要共同且一致的資料來源，以管理：

- IE 標準、工序、節拍時間、人力與每小時目標。
- 各產線目前生產的型體／款式。
- 每小時產量、實際人力、停機時間、停機原因與不良數。
- 班次進行中的產線績效與 LLER。
- 第一班與第二班可獨立且可靠地結班。
- 依產線、型體、工段、時間、日期及班次追溯歷史資料。
- 依登入者所屬廠房或指定產線限制報表存取範圍。

若缺少本系統，IE 標準與實際生產資料容易分散在不同試算表中，班次識別可能混淆，管理者也難以將生產結果追溯至特定型體與時段。

## 3. 產品目標

1. 建立 IE 標準與實際生產資料的單一營運來源。
2. 讓生產團隊能快速輸入每小時或部分班次資料。
3. 支援同一產線配置多個有效型體，且歷史資料不互相混淆。
4. 確保第一班與第二班的封存資料各自獨立且唯一。
5. 提供 IE 與管理者詳細且受權限控制的生產資訊。
6. 結班後保留完整稽核歷史。
7. 支援桌面與行動瀏覽器的現場操作，並可暫存短暫離線輸入。

## 4. 非產品目標

- 本系統不取代公司 MES。
- 目前不讀取 MES 條碼，也不將生產輸入回寫 MES。
- 不控制機台、PLC、掃描器或其他生產設備。
- 不自動決定型體應配置至哪一條產線。
- 不涵蓋薪資、出勤、倉儲或完整品質管理功能。

條碼／MES 串接屬於未來整合項目，必須使用 MES／IT 負責人核准的唯讀 API、資料庫 View 或中介服務帳號。

## 5. 使用者與權限

| 角色 | 主要職責 | 存取範圍 |
|---|---|---|
| IE 管理員 | 管理標準、型體、使用者、產線配置、監控、報表及班次歷史 | 所有已授權的生產資料 |
| IE 操作員 | 維護型體標準、監控產線、輸入允許的資料及檢視明細 | 除非組織範圍限制，否則可檢視所有產線 |
| 線長 | 輸入實際生產資料並執行結班 | 僅限指定產線 |
| 管理層 | 檢視儀表板、監控、分析及報表 | 指定廠房或全域範圍 |
| IT 管理員 | 管理使用者與技術權限 | 系統管理範圍 |
| PPIC | 設定或檢視生產目標與產線計畫 | 生產規劃相關範圍 |

所有受保護頁面及 API 都必須通過登入驗證。生產資料寫入及報表查詢都會執行產線層級的權限檢查。

## 6. 核心產品流程

### 6.1 標準與型體管理

1. IE 手動建立型體，或匯入 NB Standard Excel 檔案。
2. IE 檢查型體基本資料、工段、工序、VA／NVAN／NVA 時間、寬放率、標準人力、節拍時間及每小時目標。
3. IE 儲存型體，並可上傳型體圖片。
4. IE 將一個或多個有效型體配置至生產線。
5. 標準更新後，系統會清除相關快取，使產線、監控與 TV 畫面取得新資料。

### 6.2 實際生產輸入

1. 線長或已授權的 IE 使用者選擇可操作的產線。
2. 選擇目前生產的型體與工段。
3. 選擇第一班或第二班及生產時段。
4. 輸入產量、實際人力、停機分鐘、停機原因及不良數。
5. 伺服器確認該工段屬於此產線目前有效配置的型體。
6. 系統依產線、工段、日期及時段的唯一組合新增或更新資料。

### 6.3 半天或部分班次輸入

使用者可以只輸入實際有生產的時段，例如第一班的前半段，之後直接結班。未輸入時段會保持空白，不會自動補零。

部分班次一旦結班，整個所選班次都會鎖定。後續無法再補輸入其他時段，除非透過經授權的管理修正流程處理。

### 6.4 結班

1. 使用者確認畫面顯示的第一班或第二班。
2. 系統取得正確的生產日期；第二班跨午夜時仍歸屬於開班日期。
3. 系統確認該班已有實際資料，且尚未封存。
4. 建立封存資料與鎖定實際資料會在同一筆資料庫交易中完成。
5. 僅在交易成功後，才寄送選填的主管電子郵件。
6. 班次歷史會顯示型體、工段、時間、產量、目標、人力、停機、不良與 LLER 明細。

每一個「產線＋生產日期＋班次編號」只能存在一筆封存紀錄。

## 7. 班次規則

### 第一班

- 一般時間：07:30–16:30。
- 一般休息：12:30–13:30。
- 星期五時間：07:30–17:00。
- 星期五休息：11:30–13:00。
- 加班：正常下班後可選擇增加 1 至 3 小時。

### 第二班

- 一般時間：20:30–隔日 05:30。
- 預設休息：00:30–01:30。
- 加班：05:30 後可選擇增加 1 至 3 小時。
- 午夜後的資料仍歸屬於第二班開始當日的生產日期。

系統只支援兩個正式班次。舊資料中的「夜班」標籤會統一視為第二班。

## 8. 功能需求

### FR-1 登入與授權

- 受保護的營運頁面必須登入後才能使用。
- 系統依角色控制導覽選單與 API 權限。
- 線長只能存取被指定的產線。
- 有廠房範圍限制的使用者，只能取得該廠房報表。

### FR-2 型體資料庫

- IE 可建立、編輯、停用及檢視型體。
- IE 可維護型體文章、階段、產線類型、工段、工序、標準與圖片。
- 編輯標準時，系統必須保留歷史實際資料的關聯。

### FR-3 產線配置

- 授權使用者可將多個有效型體配置到同一條產線。
- 實際輸入只能選擇該產線有效型體所屬的工段。

### FR-4 實際生產輸入

- 授權使用者可依時段輸入產量、實際人力、停機、原因及不良數。
- 同一產線、工段、日期與時段再次儲存時，應更新原有資料。
- 休息時段或超出允許範圍的時段必須被拒絕。
- 已結班的資料不得再寫入。

### FR-5 警示與監控

- 系統應識別產量過低、停機過長及不良率過高的情況。
- 監控與 TV 畫面應顯示目前產線績效及型體資訊。
- 型體或產線配置更新後，系統應更新共用標準快取。

### FR-6 班次封存

- 第一班與第二班必須可獨立結班。
- 資料庫必須防止相同產線、日期與班次產生重複封存。
- 封存資料必須保留彙總與結班稽核資訊。
- 結束其中一班不得鎖定同一生產日期的另一班。

### FR-7 歷史、分析與匯出

- 歷史頁面可依廠房、產線、班次、日期與期間篩選。
- 歷史明細應顯示型體／款式、工段、時間、產量、目標、標準人力、理論人力、實際人力、LLER、停機、原因及不良。
- 授權使用者可將日報與班次歷史匯出為 Excel。
- 報表查詢必須與應用程式畫面使用相同的產線權限範圍。

### FR-8 語言支援

- 支援的畫面應提供印尼文、英文與繁體中文。

## 9. 資料完整性需求

- `Actual` 唯一條件：產線＋工段＋生產日期＋時段。
- `ShiftArchive` 唯一條件：產線＋生產日期＋班次編號。
- 實際資料必須連結至存在的產線、工段及輸入使用者。
- 輸入工段必須屬於所選產線目前有效配置的型體。
- 結班必須先完成封存與鎖定交易，再執行外部郵件寄送。
- 歷史重複封存必須先備份與人工確認後才能清理。

## 10. 效能與可靠性

- 監控與 TV 使用的標準資料會快取，以控制資料庫流量。
- 型體或產線配置變更後，相關標準快取會失效並更新。
- 現場輸入支援短暫斷線時的本機離線佇列。
- 畫面必須清楚顯示驗證失敗、班次鎖定、無權限及連線錯誤。

## 11. 資安與合規

- 資料庫及服務憑證必須存放於環境變數，不得提交至程式碼庫。
- 未來 MES 串接必須使用專用最小權限帳號，並優先採用唯讀 View 或 API。
- 生產資料匯出必須遵守角色、廠房及產線權限。
- 班次封存屬於稽核紀錄，不得靜默刪除。
- 資料庫遷移前必須備份並檢查重複資料。

## 12. 成功指標

- 每班有提交資料的有效產線比例。
- 結班前完成輸入的預期時段比例。
- 被安全拒絕的重複結班次數。
- 線長完成一筆每小時輸入所需時間。
- 具備型體與工段追溯資訊的封存比例。
- 監控可用性及資料更新時效。
- 人工整併試算表時間的降低幅度。

## 13. 驗收標準

1. 同一產線與生產日期的第一班和第二班可分別結班。
2. 相同產線／日期／班次再次結班時，系統清楚提示已結班，且不建立重複封存。
3. 第二班午夜後輸入仍歸屬於正確的生產日期。
4. 使用者可選擇正常工時或 1 至 3 小時加班。
5. 使用者可只輸入部分班次後結班；已輸入資料會封存，所選班次會鎖定。
6. 同一產線執行多個型體時，歷史與每小時明細會顯示所有實際使用的型體。
7. 未配置於該產線的型體工段不可提交。
8. 線長無法透過畫面或 API 存取未被指定的產線。
9. 日報匯出與分析只回傳使用者有權限的產線。
10. 型體及圖片更新後，TV／監控的快取標準會更新。

## 14. 未來規劃

- 透過 IT 核准的唯讀方式查詢 MES 條碼。
- 建立條碼與型體／款式、生產工單的對應。
- 當工廠班表穩定且確有需要時，再提供可設定班表管理功能。
- 建立具原因與核准稽核的封存重開／修正流程。
- 增加掃描器、離線恢復及同時結班情境的端到端測試。
